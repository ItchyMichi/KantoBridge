# tools/lua

Unit tests for `gen1-bridge`'s Lua, run by pytest under **lupa 2.8 on LuaJIT 2.1** (the engine's
runtime; never a bare `import lupa`, which picks Lua 5.5).

| File | Contents |
|---|---|
| `kblua.py` | `Bridge`: a fresh LuaJIT state with the sandbox, a fake `mod`, a fake socket, a fake `love.timer` whose clock tests control (`now`; `clock_per_call` makes every read cost time, for budget tests), and optionally the fake engine (`engine=True`). `module(rel)` loads a gen1-bridge file the way `main.lua` does; `run_main()` runs the entry chunk the way the loader does; `mods_loaded()` and `ready()` emit `mods.loaded` and `game.ready`; `step(n)` runs logic steps through the `input.step` hooks, then (when the fake world simulates) the engine's own part of the step; `reload()` simulates F5. Strict by default: reading an unknown global or creating one fails. |
| `rig.py` | `Rig`: `main.lua` on the fake engine with `Peer`s, fake Minecraft connections on the fake socket. Every message a peer receives is checked strictly against `protocol/` with `kb_protocol` (leg `g2m`). `Rig(world=...)` installs a made-up world for the export; `dataset_mode` makes the fake dataset view work, fail to open, or read nothing; `rig.simulate(spec)` installs a simulated overworld (`fake_world.lua`). |
| `sandbox.lua` | A copy of the environment Gen1Recomp gives mods (`src/mods/Sandbox.lua`, v0.3.49), minus the legacy compat shims. Re-check it on every Gen1Recomp pin change. |
| `fake_mod.lua` | The parts of the loader's `mod` object gen1-bridge uses (`read`, `log`, `events`, `hooks`, `input`, `options`, `ui`, `content`, `datasets`, `exports`), plus `emit` (engine events) and `call` (engine hooks). `mod.input` records every call and, when the game has a sourced input (the fake world's), presses into it as the Loader does: one source per call, releases only for this mod's tokens. |
| `fake_world.lua` | A simulated overworld for the step driver's tests, written from the engine behaviour P1 documents: an Input with per-button sources (`Input:step`, `isDown`, `reset`), char-grid maps (floor, walls, door and stairs tiles, exit mats, pads, holes, water, ledges), warps with their fades and the door walk-out, connections, ledge hops (also onto a connected map), Strength boulders, NPC steps, scripted moves in the engine's two phases, the `scripted` gate, `handleInput` (edge exits, ledges, boulders, `tryMove` with its 4-frame turn and the `movement.collision` hook), landing, warps on arrival, the Cycling Road roll, Fly/Teleport/blackout/script warps, and a per-tick trace (moving, cell, held buttons) for timing assertions. Its events and hooks go to the current mod object. |
| `fake_engine.lua` | The engine pieces `lib/kb_engine.lua` reads: a Game with a state stack, save and data, the overworld and its player (steps, landings, script moves, holds), NPCs, and the engine modules it requires (Version, GameVersion, Badges, and the Tilt/Pipelines/Zoom option appliers, which record their calls). For the export: a runtime `Map`, the neighbour BFS, tile animations and spinner tiles, image loading, and dataset views with detached copies, all written for Kanto Bridge from the engine's documented rules. All synthetic. |
| `export_world.py` | A made-up world for the export tests, shaped like the engine's records: 13 maps (a 3-map surface, houses, a gym, a lab, a cave, gates and tunnels) built so every per-cell flag, parent, `LAST_MAP` case, palette rule and swap site has a known answer; tilesets, sprites, palettes, encounters, names, field tables and small PNGs. |
| `fake_socket.lua` | LuaSocket 3.0-rc1's TCP semantics (blocking accepted clients, partial receives, send tails, busy ports) with test controls. |
| `gen_catalog.py` | Writes `gen1-bridge/lib/kb_catalog.lua` from `protocol/catalog.json` (`--check` reports staleness). Run it after a protocol change. |
| `test_lua_*.py` | The tests, marked `lua`. `test_lua_s4_spike.py` is spike S4; `test_lua_session.py` the connection rules; `test_lua_player.py` the classifier, the observer (ledge hops, tags, forced syncs) and `kb_engine.observe()`; `test_lua_move.py` the step driver and warps through `main.lua` against the simulated overworld (press/release timing, facing first, the landing release, continuous walking, the queue of 2, re-presses after an input reset, refusals, leaving idle, push steps, ledge hops, boulders, connections, every warp kind, `move.face`, `move.hold`, connections and roles, no drift); `test_lua_warp.py` the warp tracker on plain facts and `kb_engine`'s movement internals; `test_lua_options_snapshot.py` the options pin, the snapshot and the generated catalog; `test_lua_export.py` the world export: every kind against `protocol/export/`, hashes and sizes against Python's canonical JSON, crafted cell flags, the whole-world facts, the data-source fallbacks, the build and reply budgets, roles and errors. |

A note on lupa: a Python callback that reads Lua tables while a Lua coroutine is running sees the
wrong Lua state (it can get a thread back instead of a number). Code that runs inside the export's
build coroutine must call Lua functions only, so tests give it Lua clocks, never Python lambdas.

Run them with `tools/.venv/Scripts/python.exe -m pytest -c pytest.ini --rootdir . lua` from `tools/`.

`kblua.py` turns off Python's faulthandler: LuaJIT on Windows x64 raises an SEH exception for every
Lua `error()`, and faulthandler would print each one as a "Windows fatal exception".
