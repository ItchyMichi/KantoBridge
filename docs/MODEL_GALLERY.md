# Blue model gallery and comparison workflow

The gallery displays Blue's, Crystal's and Emerald's fitted voxel models, assembled objects and explicitly selected building templates on a separate flat Minecraft world. The first pilot is the repeating tree on Pallet Town's boundary: `tilesets.overworld/42-43-58-59`.

For the exact geometry/paint authoring process behind the accepted results, read [Model authoring workflow](MODEL_AUTHORING_WORKFLOW.md). To resume the full Emerald scenery and building pass after clearing context, start with [the Emerald handoff](EMERALD_MODEL_HANDOFF.md); it includes gallery size limits and coverage issues that must be resolved before a complete Emerald run.

It renders the mod's actual `ShapeTable` geometry and exported textures inside Minecraft. The exhibits are decorative preview instances, not gameplay blocks or collidable entities. Open the gallery through this workflow when revisiting it; its manifest supplies the exhibits. Normal Kanto saves and the hidden game are not used.

## Run the pilot

From the repository root in PowerShell:

```powershell
.\tools\model_gallery.ps1
```

To compare the preserved original tree with the current one in the same session:

```powershell
.\tools\model_gallery.ps1 -BaselineTable local/model-gallery/baseline-blue.json
```

The wrapper prepares the references, starts the development client, captures front and side views, closes that client, and assembles comparison sheets. The default output is `local/model-gallery/pallet-trees/`:

Use `-North` (Python `prepare --north`) for a supplemental view from the north looking south, such as the Cave of Origin exit approach. It adds a distinctly named `north` capture after the regular views and a separate `*_north.png` comparison sheet. Its original screenshot hashes and exact coverage are required in the report; it does not relabel a front view or change the default cameras. Combine with `-Angled` when both elevated and north views are needed.

- `index.html`: local comparison gallery; open in a browser.
- `sheets/*.png`: one sheet per model, containing the sprite and Minecraft front/side screenshots. With a baseline, both old and current views appear on the same sheet.
- `contact-sheets/*.png`: pages of 12 current models, each with its sprite, front and side. Start here for a quick review, then open an individual comparison for detail. Every page is linked from `index.html`.
- `screenshots/*.png`: original, uncropped Minecraft frame captures.
- `sprites/*.png`: original-resolution sprites reassembled from the exported sheets.
- `pallet-map.png`: Pallet Town rebuilt from its tile sheet and block layout.
- `manifest.json`: source cell identities, occurrences, geometry hashes, assembly positions and camera subjects.
- `fitted-current.json` and, when supplied, `fitted-baseline.json`: exact-byte copies of the fitted tables used to prepare this gallery.
- `capture.json`: Minecraft capture status, manifest hash, image dimensions and camera poses.
- `sheet-report.json`: completeness and provenance checks, exact subject/view coverage, and the dimensions and SHA-256 of every source image and screenshot used in each comparison.

The wrapper seeds the first-run options only when its isolated client has no options file. Reopening a marked gallery automatically uses Minecraft's backup-and-load action for the experimental-world prompt. Neither step changes another Minecraft instance.

## All Blue models

```powershell
.\tools\model_gallery.ps1 -Subset all
```

The initial baseline catalog had **492 individual fitted voxel cells and 37 deduplicated compound objects**. The full improvement pass adds further complete-object exhibits; the prepared manifest is the authority for the current compound count. Compound objects include every complete stack declared by the fitted table's `on` links, plus the explicit multi-cell entity definitions in `tools/shape_fit/entities/blue.json`. Stacked rows are placed vertically; horizontal pairs remain side by side. A model that also appears in a compound retains its individual exhibit so defects can be traced to the source cell.

The catalog excludes 34 building templates and the one entry marked `columns`. The initial baseline contained six fitted entries with empty occupancy; its manifest entries and comparison sheets identify those runtime fallbacks for review. It covers the fitted scenery model table, rather than NPCs, Cobblemon species, or every context-sensitive terrain/building fragment generated by the world planner. This scope is recorded in the manifest.

The full run takes much longer than the one-tree pilot because each model receives two settled camera views. Models stand on a regular grid with space between exhibits. Front means looking north at the object's south face; side means looking west at its east face. Minecraft uses the same field of view for all captures, positions the camera from the model bounds, hides the HUD and labels during capture, and records the camera pose. Sprite panels use nearest-neighbour scaling and are centered without stretching.

To reopen a prepared gallery interactively without taking new screenshots or changing its manifest:

```powershell
.\tools\model_gallery.ps1 -Subset all -View
```

Use `-PrepareOnly` first if that output folder does not yet contain a manifest. The same `-View` option works for the Pallet pilot and a custom `-OutDir`.

Prepared galleries retain their model revision even after the mod's fitted table changes. Minecraft verifies `fitted-current.json` against the manifest's source checksum and loads it only within the gallery geometry build; a mismatched snapshot fails clearly. Baseline comparisons also use their local, checksum-verified copy. Running prepare again deliberately replaces these snapshots and the manifest with the latest source revision, so use a new output folder to preserve a historical comparison.

For galleries prepared before snapshots were introduced, an exact copy of their original fitted table can be placed beside the existing manifest as `fitted-current.json`. Its SHA-256 must equal `source.table_sha256`. This backfill preserves the manifest and capture evidence byte for byte; neither viewing nor snapshot loading rewrites them. A legacy gallery without a snapshot can still resolve models present in the current mod table.

## Repeat an improvement pass

1. Preserve the fitted table in an ignored local baseline file before editing it. Keep that file with the comparison results.
2. Prepare a focused manifest and inspect the source sprite and map context. Identify whether the defect is background masking, silhouette, volume, assembly or paint projection.
3. Correct the model in its generation source. Use explicit geometry or a hand model when the object's structure needs it. Update only the relevant fitted entry and preserve its dimensions and intended interactions.
4. Run the pilot with `-BaselineTable` to render old and new hashes together. Inspect both directions and the sprite before accepting the change.
5. Run relevant geometry tests. Regenerate the full manifest after accepting a change so it contains the current hashes. Use the full catalog to check repeated uses and compound objects.

The Pallet tree's reproducible geometry source is `tools/shape_fit/pallet_tree.py`. Its generated model remains in the Blue fitted table; the gallery itself does not rewrite any models.

For later focused passes, select exact catalog IDs, labels or individual cell keys with `-Only`. Give each pass its own output folder:

```powershell
.\tools\model_gallery.ps1 -Only 'tilesets.overworld/42-43-58-59' -OutDir local/model-gallery/tree-pass
```

`-Only` accepts several strings, such as `-Only id1,id2`, and searches the full catalog. Its default output is `local/model-gallery/selection/`, leaving the pilot and full-gallery outputs intact. A cell key selects its individual exhibit; select a compound by the ID recorded in the full manifest. Unknown selectors fail before writing output, so a typo cannot silently produce an incomplete pass. Baseline comparisons apply to the selected exhibits automatically. The Python equivalent uses repeatable `--only` options:

```powershell
python tools/model_gallery.py prepare --subset all --only tilesets.overworld/42-43-58-59 --out local/model-gallery/tree-pass
```

Use `-Map` when a shared model should be reviewed in one map's palette. The selected model must occur in that map; the sprite and every geometry fragment use the same occurrence palette. `source-map.png` records the reconstructed map context. For a low object whose controls face upwards, `-Angled` adds a third view at 30 degrees elevation and a separate `*_detail.png` comparison, while preserving the normal front/side sheet:

```powershell
.\tools\model_gallery.ps1 -Only 'tilesets.reds_house/14-15-30-31' -Map REDS_HOUSE_2F -Angled -BaselineTable local/model-gallery/bedroom-console-baseline.json -OutDir local/model-gallery/bedroom-console
```

The Python equivalents are `--map REDS_HOUSE_2F --angled`. The manifest's `views` list defines exact capture coverage; older manifests still default to front and side only. This avoids accidentally reviewing the bedroom console with the palette of its other occurrence in Copycat's house.

The console trial changes only `tilesets.reds_house/14-15-30-31`. Its new explicit geometry separates a low case with a recessed slot and raised controls, a diagonal controller, and a cord resting on the ground. Explicit surface paint keeps these details readable from the side as well as above. Occupied voxels decrease from 617 to 302 as the automatic sprite extrusion is replaced by the individual parts. The shared cell also updates the console in Copycat's room; the adjacent television is a separate, unchanged model. Six actual Minecraft captures compare the original and revised console in the bedroom's PALLET palette.

This tree appears 66 times inside Pallet Town's map. The new model has a rounded crown, a narrow stem, and wrapped source texels, removing the old cast-shadow slab and broad black side projection. Removing the projected sprite outline also softens the front contour; the before/after sheet makes that tradeoff visible. The existing Red-to-Blue table sharing means Red uses the change too.

Existing Kanto worlds store the previous model hash in their shape index. Build a new world or rebuild its shapes to adopt the revised tree. The gallery uses the new hash directly and leaves existing saves untouched.

## Blue full improvement pass

The pass audits every fitted voxel cell against its source sprite, reconstructed map context, and the initial Minecraft front/side gallery in `local/model-gallery/all/`. The preserved input is `local/model-gallery/blue-rollout-baseline.json`; do not replace it with the revised table. Authoring sources are `tools/shape_fit/blue_pass/outdoors.py`, `props.py`, and `interiors.py`, with shared encoding helpers in `common.py`. Their per-cell decisions, local geometry previews and generated patches are under the corresponding `local/model-gallery/blue-rollout-study/` subdirectories. Local previews support modelling; the final review uses actual Minecraft captures.

The merged pass contains **319 revised cells, 4 added cells and 173 retained cells**. The current catalog has **560 exhibits: 496 individual cells and 64 complete objects**. These are model and catalog counts; successful capture still requires the verification reports described below.

Regenerate all three patches, then validate coverage and merge them:

```powershell
python -m tools.shape_fit.blue_pass.outdoors
python -m tools.shape_fit.blue_pass.props
python -m tools.shape_fit.blue_pass.interiors
python tools/shape_fit/blue_pass/review.py `
  --baseline local/model-gallery/blue-rollout-baseline.json `
  --patch local/model-gallery/blue-rollout-study/outdoors/updates.json `
  --ledger local/model-gallery/blue-rollout-study/outdoors/review.json `
  --patch local/model-gallery/blue-rollout-study/props/updates.json `
  --ledger local/model-gallery/blue-rollout-study/props/ledger.json `
  --patch local/model-gallery/blue-rollout-study/interiors/updates.json `
  --ledger local/model-gallery/blue-rollout-study/interiors/review-ledger.json `
  --patch local/model-gallery/blue-rollout-study/interiors/additions.json `
  --ledger local/model-gallery/blue-rollout-study/interiors/additions-ledger.json `
  --report local/model-gallery/blue-rollout-study/review.json --write-table
```

Use `--check` instead of `--write-table` in the same command, keeping all four patch/ledger pairs, to verify that the bundled table equals the reviewed result. The merger requires an explicit decision per fitted cell, rejects overlapping patch ownership and empty replacements, and preserves building templates, the non-voxel cemetery entry, and the approved Pallet tree and bedroom console. The separate additions ledger records four previously missing rear cells of the museum mineral case. These added models have source/current comparisons only; an absent baseline is not presented as an old fitted model. Existing source identities and interaction metadata remain intact except for three documented incorrect `on` links: the Facility bed, ship cabin bed, and Pokémon Center patterned floor pair are horizontal neighbours rather than vertical stacks.

After further visual corrections, add `--replace-reviewed` alongside `--write-table` to replace the previous reviewed result. Keep the prior report at `--report` until this command succeeds: its `table_sha256` must match the current bundled table byte for byte, and its `baseline_sha256` must match the preserved input. The guard rejects unrelated intervening table changes; it does not permit an arbitrary overwrite.

The complete-object catalog in `tools/shape_fit/entities/blue.json` includes explicit floor assemblies for those corrected pairs and additional exhibits such as the four-cell Safari Zone tree, Fan Club sofa, Bill's transporter and long ship cabin bed. These exhibits show joins and proportions that cannot be judged from isolated cells. Corrected pairs retain their comparison identities so the baseline can show the former vertical placement beside the revised horizontal assembly.

Capture the complete baseline/current comparison in its own output directory, then build the searchable review page:

```powershell
.\tools\model_gallery.ps1 -Game blue -Subset all -Angled -SettleTicks 3 `
  -BaselineTable local/model-gallery/blue-rollout-baseline.json `
  -OutDir local/model-gallery/blue-review
python tools/shape_fit/blue_pass/report.py `
  --gallery local/model-gallery/blue-review `
  --ledger local/model-gallery/blue-rollout-study/review.json
```

`local/model-gallery/blue-review/` is the canonical review output. The first full pass in `local/model-gallery/blue-rollout/` remains preserved; its images exposed wandering Cobblemon in some backgrounds. The wrapper sets `enableSpawning: false` only in the isolated `local/model-gallery-client/config/cobblemon/main.json`. The gallery also disables vanilla mob spawning and clears loaded non-player entities, including saved creatures, only inside its marked gallery world. This cleanup keeps source models in focus without changing a gameplay client's configuration or normal world entities.

`review.html` filters models by source key, semantic label, map, atlas, changed/retained/added decision and complete-object status. Its linked comparison sheets contain the source sprite and Minecraft views of both revisions where a baseline exists; added models show source/current evidence. The full run requests front, side and angled views so controls and other low details can be inspected. `review-ledger.json` records the reason for each decision. Build the report only after capture and sheet verification finish. Final counts and completion evidence come from that run's manifest and reports, not the earlier baseline gallery. Use the same wrapper command with `-View` to reopen its prepared world without recapturing.

This workflow changes the fitted scenery table and comparison exhibits. Existing gameplay worlds retain their recorded shape hashes until rebuilt; a new world or shape rebuild is needed to adopt the revised models. Shared Red/Blue fitted entries also affect Red. Existing saves and the preserved historical gallery remain untouched by preparing a separate review gallery.

## Options and direct tools

`-OutDir` selects another folder under this repository's ignored `local/`. `-Bundle` selects an existing Blue export. `-PrepareOnly` writes the manifest and references without opening Minecraft. `-View` opens an existing gallery interactively without preparing or capturing it. `-SheetsOnly` recomposes completed captures and contact sheets without starting Minecraft. `-KeepOpen` leaves the client open after captures; close it to let the wrapper finish the sheets. `-SettleTicks` adjusts the pause between camera movement and capture, from 2 to 200 ticks.

Interactive viewing writes `view-session.json` and preserves the completed `capture.json` and its screenshot evidence.

The wrapper tries the project Python environment, `KB_PYTHON`, PATH, and the bundled Codex Python runtime. It requires Pillow. If this machine's old `.venv` points to a removed interpreter, pass a working interpreter with `-Python`; no system installation or PATH changes are needed. JDK 21 can be selected with `-JavaHome` or `KB_JAVA_HOME`.

Equivalent Python commands are:

```powershell
python tools/model_gallery.py prepare --subset pallet-trees --out local/model-gallery/pallet-trees --baseline-table local/model-gallery/baseline-blue.json
python tools/model_gallery.py sheets --manifest local/model-gallery/pallet-trees/manifest.json
```

`sheets` exits with status 1 if a view is missing or unreadable, capture is incomplete, `capture.json` does not match the manifest hash, or the recorded subject/view set has omissions, duplicates or unexpected entries. Existing screenshot filenames alone cannot establish a successful run. The generated sheet can still be inspected, but the report records it as incomplete. Do not regenerate a manifest during an active capture.

All reconstructed sprites, map art, screenshots, baseline tables and generated worlds stay in `local/`. The tool reads exported image, tileset and map JSON; it does not read a ROM or a hidden-game save, start Gen1Recomp, or obtain screenshots from the hidden game.

## Explicit whole-object placements and honest baselines

An entity may provide `placements`, one record for every nonempty `layout` cell:
`{"source":[column,row],"offset":[x,y,z]}`. Offsets use whole source-cell units
(16 voxels, two Minecraft blocks). This supports objects combining true vertical
layers with a projected foot on the floor. Coordinates must be bounded integers;
duplicate, missing or overlapping placements fail preparation.

`baseline_layout` may mask only source cells that were actually unrendered before
the change. `baseline_placements` records the old geometry positions. Both retain
the complete source through `reference_layout`. Automatic stack identities stay
stable; equivalent explicit definitions become aliases. Distinct old layouts
retain separate comparison identities even when masking makes them identical.

Missing fitted entries at SOLID source cells are not necessarily invisible. A
source-map planner fixture may supply `baseline_native_cells` with the exact four
native CUBE columns, their map, original table hash and evidence hash. The gallery
validates and displays those columns for both individual and complete-object
before companions without inventing fitted entries or changing the baseline
table. Conflicting contexts, existing fitted keys, mismatched baseline hashes
and non-CUBE evidence are rejected. The school chalkboard's three missing entries
use this path because its baseline planner produced six-block native walls.

New preparations also save exact `entities-current.json` bytes and their hash
beside the table snapshots. Capture completion still requires exact screenshot
coverage and separate manual visual review.

An exact `baseline_native_fragments` descriptor handles existing fitted cells
that the original source-map planner bypassed with native CUBE/ROOF columns.
It pins the original table SHA, the complete runtime-proof file SHA, one exact
map occurrence and its complete source layout. Preparation checks map bytes,
source collision, original voxel hashes, documented shape keys and contiguous
carrier columns. The override applies only to that before exhibit. Its loaded
proof is embedded in the manifest and preserved in the history index.
An optional proof `source_mask` must exactly match the exhibit's nonempty cells;
all recorded carrier positions must stay inside it. This excludes unrelated
room-wall columns from Mossdeep's complete counter-bank comparisons while
retaining the full source drawing and the actual original counter dispatch.

A gallery-only entity with `building_baseline: true` and a new building's ID
can pair that current template with an original source-map compound. It cannot
replace an existing original template or modify production building metadata.
`python -m tools.shape_fit.emerald_pass.native_baselines --proof <proof.json>
--out <entities.json>` reproducibly binds these companions. The environment
templates use eight representatives from a tested 46-occurrence runtime proof.

The narrow `elite-open-arch-v1` proof mode additionally pins `g3sites/all.json`
and reconstructs the Elite rooms' built open source states using G3Built's
ground-before-solid selection with the map's own state winning ties. Raw source
inventory remains intact. Closed Elite leaves continue to use the existing
native story renderer, pass, height and per-state art; they are not fitted-model
additions. Complete capture coverage still requires manual visual inspection.

`generic-interior-arch-v1` is restricted to the Trick House Entrance rectangle
`(4,0)` of size `3x2` and its single story site `(5,1)`: raw solid metatile539
normalizes to metatile537 with collision114. The runtime scene marks it WALK
without a WARP tag; the gallery does not add one. The same raw map/sites hashes
and native closed-state checks apply. Other maps, rectangles, sites and state
transitions are rejected.

`current_native_fragments` supports exact current source-map exhibits when the
ordinary catalog layout differs from runtime placement. Its descriptor pins
`evidence`, `evidence_sha256`, `current_table_sha256`, `occurrence`,
`source_layout`, `source_cell_hashes`, and `source_template_hashes`. The proof's
current table revision must agree, and every participating cell's complete
metadata and geometry must still match its canonical JSON hash. Exact templates
intersecting the source rectangle are also hashed, so a newly matching template
invalidates an earlier cell-column proof. Unrelated table edits remain allowed.
Current fitted fragment keys are checked against the current table's actual
voxel/paint hash. Source bytes, collision, placement bounds and documented shape
keys receive the same checks as original native companions.

This gallery-only override uses `corrected_fragments` and reports
`placement_mode: source-map-current`; the before companion separately uses
`original_baseline_fragments`. Both descriptors and loaded evidence are retained
in manifests and archives. Different map contexts remain separate exhibits when
their native floor material or neighbor clipping changes the shape keys. The
QA10 ship miniature therefore has three exact representatives, rather than one
layout that claims identical rendering at all four source occurrences.

## Gallery shutdown after automatic capture

An automatic gallery with `kantobridge.gallery.quit=true` first saves the complete
`capture.json`, then keeps the same marked integrated server ticking for at least
100 server ticks. It requests normal Minecraft shutdown only after 20 distinct
quiet server ticks with no generation references, queued generation tasks or
unfinished chunk save dependencies. The read-only `GalleryChunkMapAccessor` is
enabled only by the explicit gallery manifest property; it never changes tickets,
chunk references or gameplay shutdown.

`shutdown.json` records this separate drain phase and its counters. A changed
server/world, missing `model-gallery.json` marker or a 1200-tick drain timeout
cancels the automatic stop. Screenshot completion remains intact even when
shutdown cannot finish. The final client-thread stop rechecks the same server,
resolved world directory and marker. `GalleryShutdownTest` and the dev-mixin gate
test cover these lifecycle boundaries; a real capture run verifies clean exit.
